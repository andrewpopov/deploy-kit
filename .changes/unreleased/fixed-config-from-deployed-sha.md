---
kind: fixed
summary: deploy loads .deploy-kit.config.json from the commit being shipped, not the checkout it runs in (PKG-318)
---

A stale checkout (or, for a deploy-kit run on the host, the host's old checkout) used to supply the hooks, checks, protections and monitor settings for a newer commit. `deploy()`, `deployRelease()` and `deploy --on-host` now settle the final sha first (`--sha`, the `requireVerifiedRef` tip, or the branch tip pinned as `--sha`) and re-read a file-loaded config from it through the same loader and validation, before preflight, locks, protections and checks, with the notice `deploy-kit: using .deploy-kit.config.json from <sha8> (the working tree differs)`. The sha's file is read from the controller checkout, fetching the exact sha from any remote it has. A commit without the file, an unfetchable sha, a branch tip that moves before checkout, or a sha whose `mode`, `host`, `projectDir`, `ssh`, `remote`, `branch`, `requireVerifiedRef`, `autoCut` or `layout` differs from the working tree is refused. Auto-cut ships the tip's config and refuses a cut that changed it. `--dry-run` fails closed on a local commit with no config. Configs built in code, or loaded outside a git checkout, are used as given.
